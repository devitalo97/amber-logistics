
# ADR-001: Relational Spatial Data Model for Amber Logistics

## Context & Architectural Design

To prevent high-coupling and handle multi-leg transportation workflows without generating a schema full of conditional nullable Foreign Keys, we implement a **Table Inheritance / Polymorphic Data Pattern**.

A single base table (`points_of_transit`) registers every geographic node in the supply chain. Specific entities—whether internal (`brand_sites`), external (`suppliers`), or public infrastructure (`infrastructure_hubs`)—maintain a strict 1:1 structural relationship back to this base table. Consequently, a transport segment (`shipment_leg`) simply connects an origin `point_id` to a destination `point_id`, completely agnostic to the nodes' underlying business classifications.

## Database Schema (DDL)

```sql
-- 1. Enums & Custom Domain Types
CREATE TYPE point_type AS ENUM ('supplier', 'brand_site', 'seaport', 'airport', 'logistic_hub');
CREATE TYPE brand_site_type AS ENUM ('distribution_center', 'warehouse', 'retail_store');
CREATE TYPE hub_type AS ENUM ('seaport', 'airport', '3pl_facility');
CREATE TYPE transport_mode AS ENUM ('sea', 'air', 'land');

-- 2. Core Base Abstraction Table
CREATE TABLE points_of_transit (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    name VARCHAR(255) NOT NULL,
    type point_type NOT NULL,
    
    -- Geospatial Data (Decimal Degrees for Map Rendering & Proximity Queries)
    latitude DECIMAL(10, 8) NOT NULL,
    longitude DECIMAL(11, 8) NOT NULL,
    
    -- PostGIS Native Support (Uncomment for production spatial indexing)
    -- coordinates GEOMETRY(Point, 4326),
    
    country_code CHAR(2) NOT NULL, -- ISO Alpha-2 (e.g., 'CN', 'US')
    city VARCHAR(150) NOT NULL,
    address_line_1 VARCHAR(200) NOT NULL,
    address_line_2 VARCHAR(200),
    postal_code VARCHAR(20) NOT NULL,
    state VARCHAR(50) NOT NULL,   -- Supports global state/region formats
    time_zone VARCHAR(50) NOT NULL, -- IANA Time Zone Database format
    created_at TIMESTAMP WITH TIME ZONE DEFAULT CURRENT_TIMESTAMP,
    updated_at TIMESTAMP WITH TIME ZONE DEFAULT CURRENT_TIMESTAMP
);

-- 3. Specialized Extension Tables (1:1 Relationships)
CREATE TABLE brand_sites (
    point_id UUID PRIMARY KEY REFERENCES points_of_transit(id) ON DELETE CASCADE,
    sub_type brand_site_type NOT NULL,
    storage_capacity_cbm DECIMAL(10, 2), -- Capacity in Cubic Meters (m³)
    operational_status VARCHAR(50) DEFAULT 'active'
);

CREATE TABLE infrastructure_hubs (
    point_id UUID PRIMARY KEY REFERENCES points_of_transit(id) ON DELETE CASCADE,
    sub_type hub_type NOT NULL,
    iota_icao_code VARCHAR(10), -- Standardized global coding (e.g., 'LAX', 'PVG')
    operating_carrier_name VARCHAR(150) -- Populated if non-public carrier hub (e.g., 'FedEx Hub')
);

-- 4. Master Data Operators
CREATE TABLE carriers (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    name VARCHAR(150) NOT NULL UNIQUE, -- E.g., 'FedEx', 'COSCO Shipping', 'DHL Express'
    company_tax_id VARCHAR(50),        -- Tax Identification (EIN / CNPJ)
    contact_email VARCHAR(255),
    contact_phone VARCHAR(50),
    is_active BOOLEAN DEFAULT TRUE,
    created_at TIMESTAMP WITH TIME ZONE DEFAULT CURRENT_TIMESTAMP,
    updated_at TIMESTAMP WITH TIME ZONE DEFAULT CURRENT_TIMESTAMP
);

-- 5. Multi-Leg Routing Ledger Table
CREATE TABLE shipment_legs (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    shipment_id UUID NOT NULL, -- Corresponds to an active Shipment or a simulated container state
    sequence_order INT NOT NULL, -- Sequenced sequence: 1 (Inland Origin), 2 (Main Leg), 3 (Inland Dest)
    
    -- Domain Polymorphism Links
    origin_point_id UUID NOT NULL REFERENCES points_of_transit(id),
    destination_point_id UUID NOT NULL REFERENCES points_of_transit(id),
    
    mode transport_mode NOT NULL,
    carrier_id UUID REFERENCES carriers(id) ON DELETE SET NULL, -- Nullable to support unmapped simulation mock data
    estimated_freight_cost DECIMAL(12, 2) NOT NULL,
    estimated_transit_days INT NOT NULL,
    estimated_eta DATE NOT NULL
);

```
