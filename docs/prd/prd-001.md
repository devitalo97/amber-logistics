# PRD-001: Amber Logistics (v1.0.0)

## 1. General Overview

**Amber Logistics** provides brands with global supply chains a single, centralized plane to manage their internal fulfillment network (*Brand Sites*) and model multi-leg transport pathways. By introducing internal locations into the platform, Amber closes the loop between external manufacturing (*Suppliers*) and physical distribution networks, replacing opaque freight calculations with a deterministic routing simulation.

## 2. Personas and Actors

* **Brand Operator / Logistics Manager:** Needs to optimize destination routes, monitor downstream inventory velocity, and minimize total landed costs.

## 3. Functional Requirements

### [FR01] Brand Site Onboarding & Provisioning

* The system MUST allow operators to register internal nodes of their distribution network, classifying them as Distribution Centers, Warehouses, or Retail Stores.

### [FR02] Brand Site Micro-Intelligence Dashboard (Detail View)

* The system MUST aggregate and display the count of incoming active `Shipments` bound for the specific site.


* The system MUST leverage geospatial calculations to display the nearest infrastructure hubs (`Seaports`, `Airports`, `3PL Facilities`) and adjacent `Brand Sites`.

### [FR03] Global Supply Chain Control Tower (List & Map View)

* The system MUST render an interactive global map displaying all registered `Brand Sites`.
* The map MUST support context filters to overlay active `Suppliers` and visualize real-time polyline transit routes for ongoing `Shipments`.

### [FR04] Amber Logistics Simulator (ALS Engine)

* The system MUST allow operators to execute an end-to-end multi-leg transit simulation starting from a `Supplier` origin (or linked directly to an active `Purchase Order`) down to the target destination `Brand Site`.

* The ALS engine MUST break down the simulation into sequential, decoupled transport segments (`Shipment Legs`), estimating individual costs, carriers, and transit times for each modal leg.
